# Codex 사용량과 리셋권

개인 PC에서 실행하는 조회 전용 웹앱입니다. Codex의 5시간·주간 잔여량과 리셋권 상태를 한국 시간으로 보여주며, 리셋권을 사용하거나 모델을 실행하지 않습니다.

## 요구 사항과 실행

- Node.js 24 이상과 ChatGPT 계정으로 로그인한 Codex CLI 또는 ChatGPT 데스크톱 앱이 필요합니다. API 키 로그인은 지원하지 않습니다.
- 데스크톱 앱에서 이미 ChatGPT로 로그인했다면 같은 OS 사용자로 실행하세요. App Server가 데스크톱 앱과 같은 `CODEX_HOME` 및 OS 자격 증명 저장소를 사용해야 합니다. 그렇지 않으면 먼저 로그인합니다.

  ```sh
  codex login
  npm start
  ```

- CLI는 `CODEX_CLI_PATH`, `PATH`의 `codex`, 설치된 ChatGPT 앱·패키지 순으로 찾습니다. 경로를 직접 지정하려면 `CODEX_CLI_PATH`를 설정하세요.
- 서버는 사용 가능한 임의 포트를 골라 `127.0.0.1`에만 연결하고 기본 브라우저를 엽니다. 종료하려면 터미널에서 `Ctrl+C`를 누르세요.
- 브라우저가 열리지 않으면 기본 브라우저 설정을 확인하고 앱을 재시작하세요.
- 첫 접속은 자동으로 열린 브라우저에서 완료해야 합니다. 다른 브라우저·시크릿 창을 쓰거나 쿠키를 삭제했다면 앱을 재시작하세요. 앱을 종료하면 기존 접속 권한은 무효화됩니다.
- 실행에는 별도 런타임 패키지가 필요하지 않습니다. 인증 설정과 문제 해결은 [인증 안내](docs/authentication.md)를 참고하세요.

## 화면과 기능

- 상단 요약은 5시간·주간 잔여율, 리셋 추천, 사용 가능한 리셋권 개수와 조회된 항목 중 가장 가까운 만료를 표시합니다.
- 상세 화면은 `리셋 상세`, `만료 캘린더`, `알림` 탭으로 나뉩니다. 리셋 추천은 상단 요약 카드에서 확인하고, 판단 근거는 카드 안에서 펼쳐 봅니다. 탭 선택은 `?tab=...` 주소에 기록되며 새로고침과 뒤로 가기에서 복원됩니다.
- 탭은 키보드 방향키·Home·End로 이동할 수 있습니다. 조회 중 상태와 토글 상태를 보조 기술에 알리고, 매초 바뀌는 카운트다운은 반복해서 읽지 않습니다.
- 화면 색상은 시스템 밝기 설정을 따릅니다. 사용량 상태 변경에는 짧은 모션을 쓰며, `prefers-reduced-motion`이 설정된 경우 모션을 줄입니다.

### 요약과 정확한 시각

- 공통 요약은 짧은 추천과 정확한 권장 마감을 표시하고, 추천 탭은 대상 리셋권과 전체 근거를 제공합니다. 부분 목록·만료 불명·이전 조회 결과 안내는 요약에서도 확인할 수 있습니다.
- 모든 시각은 KST입니다. 요약은 `오늘 20:30`, 같은 해의 다른 날짜는 `10/05 00:00`, 다른 해는 연도를 포함해 표시합니다. 각 한도와 조회 정보의 `정확한 시각`을 펼치면 초·시간대가 포함된 전체 값과 초 단위 남은 시간을 확인할 수 있습니다.
- `20시 사용을 추천합니다!`와 실제 마감 `오늘 20:30`은 각각 추천 정시와 정확한 권장 마감입니다. 재조회 후 마감이 이미 지났다면 `권장 마감 경과`를 표시합니다.
- 1024px 이상에서는 잔여 한도·추천과 캘린더·선택 일정이 좌우로 배치됩니다. 좁은 화면에서는 위아래로 배치하고, 확대된 숫자가 공간을 벗어나면 한도 영역도 줄바꿈됩니다.
- 하단 `데이터 안내`는 키보드로 펼칠 수 있습니다. 현재 오류·사용 제한·부분 목록은 접힌 안내와 별개로 화면에 표시합니다.

### 잔여량과 리셋 추천

- 5시간·주간 한도는 `windowDurationMins` 300·10080으로 식별합니다. 잔여율은 조회 응답의 `100 - usedPercent`이며, 마지막 조회 시각과 리셋 시각을 KST로 보여줍니다.
- 사용 가능한 리셋권 중 만료가 가장 가까운 항목을 기준으로 추천합니다. 부분 목록은 조회된 항목 기준입니다. 만료까지 7일 이상이면 `자유롭게 사용`, 24시간 초과·7일 미만이면 사용 준비를 안내합니다.
- 24시간 이내이면 만료 1시간 전을 권장 마감으로 안내합니다. 제목은 KST 이전 정시로 `nn시 사용을 추천합니다!`를 표시하며, 해당 정시가 현재보다 과거이면 즉시 사용을 안내합니다. 정확한 권장 마감은 별도로 표시합니다.
- 조회 실패·연결 끊김·서버 사용 제한이나 이전 추천·만료·한도 리셋 시각 경과 시 추천을 보류하고 재조회를 안내합니다. 성공 조회 후 상태를 다시 판단합니다. 리셋권 없음·개수만 제공·만료 없음·만료 불명은 구분합니다.
- 상단 카드와 추천 탭은 같은 결과를 표시합니다. 추천은 기한 기준이며 사용 권한을 보장하지 않습니다. 소모 속도, 소진 예상 시각, 미래 잔여량과 작업 일정 계산은 제공하지 않습니다.

### 만료 캘린더

- KST 월간 캘린더에서 리셋권 만료는 **주황색**, 주간 한도 리셋은 **파란색**, 5시간 한도 리셋은 **회색**으로 표시합니다. 범례와 항목명을 함께 제공하며 같은 날짜의 일정도 각각 구분합니다.
- 이전 달·다음 달·이번 달 이동 및 날짜 선택을 지원합니다. 선택 날짜의 일정은 시각순이며, 같은 시각은 리셋권 만료 → 5시간 리셋 → 주간 리셋 순입니다. 날짜에서 방향키·Home·End를 사용할 수 있습니다.
- 일정의 정확한 시각을 펼친 상태와 키보드 포커스는 시간 갱신·동일 데이터 재조회에서 유지합니다. 선택 날짜 제목에는 일정 건수를 표시합니다.
- 서버가 제공한 다음 리셋만 표시하며 반복 일정이나 과거 사용 이력을 만들지 않습니다. 날짜가 없는 리셋권은 별도 안내합니다. 실패 시 마지막 성공 일정을 유지하고, 계정 변경·로그아웃 시 일정을 지웁니다.
- 선택한 월·날짜는 메모리에만 유지됩니다. 탭 식별자는 `credits`, `calendar`, `alerts`이며, 기존 `schedule`·`forecast` 링크는 `credits`로 정규화합니다.

### 알림

- 사용 추세와 추세 전용 자동 조회·표본 수집은 제거했습니다. 화면 진입·수동 새로고침·알림 확인 시점에 사용량을 조회하고, 브라우저 뒤로 가기로 페이지가 복원되면 한 번 재조회합니다.
- 만료 알림은 ID와 만료 시각이 확인된 사용 가능 리셋권에 대해 24시간 전·1시간 전에 보냅니다. 알림 직전에 다시 조회해 항목이 여전히 유효한지 확인합니다.
- 사용량 알림은 5시간·주간 리셋 30분 전, 성공 조회에서 잔여량이 20% 이하로 확인될 때, 지난 리셋 뒤 새 리셋 시각이 확인될 때 알립니다. 잔여량 감지만을 위한 주기적 조회는 하지 않습니다.
- 알림은 브라우저 앱·탭이 열려 있을 때만 동작합니다. 브라우저 알림·저장소·암호화·탭 간 잠금 기능과 알림 권한이 필요하며, 설정은 같은 앱 주소의 탭 사이에서 공유됩니다. 사용량 알림은 발송 전에 다시 조회하고, 조회 실패 시 확인을 멈춥니다. 새 리셋 시각을 확인하지 못한 경우 1분 뒤 재확인합니다.

## 조회 결과 해석

- 전체 사용 가능 개수는 서버의 `availableCount`를 표시하며, 상세 목록의 길이와 다를 수 있습니다. 상세 상태는 정보 없음·개수만 조회·부분 조회·전체 조회를 구분합니다.
- 상세 목록은 사용 가능·사용 처리 중·사용 완료·상태 확인 불가를 구분하고, 만료 시각이 확인된 항목부터 빠른 순서로 표시합니다. `expiresAt: null`은 만료 없음이며, 필드가 없거나 잘못된 값은 만료 시각 확인 불가입니다. 지급 시각으로 만료 시각을 추정하지 않습니다.
- 잔여율이 0%이거나 리셋 시각이 지나도 자동으로 한도 복구나 리셋권 사용을 가정하지 않습니다. 최신 상태는 새로고침으로 확인하세요.
- 일시적인 조회 실패에는 마지막 성공 결과와 조회 시각을 유지합니다. 로그아웃이나 계정 변경이 확인되면 이전 계정의 조회 결과와 캘린더 선택 상태를 지웁니다.
- 5초마다 확인하는 연결 상태는 로컬 서버가 기억하는 연결·인증 상태만 확인하고 새 사용량을 조회하지 않습니다. 외부에서 변경된 계정 상태가 즉시 감지된다고 보장하지 않습니다.
- 같은 앱 주소의 여러 탭에서 동시에 조회하면 브라우저가 조회를 조정하고, 지원되는 경우 진행 중인 요청의 화면용 결과를 일시 공유합니다. 이 결과는 저장하지 않습니다.
- 카운트다운은 PC 시계를 기준으로 합니다. 시계가 잘못되었거나 조회 이후 상태가 바뀌면 표시가 실제 상태와 다를 수 있습니다.

## 구조와 보안

- 조회 흐름은 `브라우저 → 127.0.0.1 로컬 서버 → Codex App Server(stdio) → Codex 서비스`입니다.
- 서버는 App Server 초기화와 `account/read`, `account/rateLimits/read` 조회만 사용합니다. 인증 파일이나 토큰을 직접 읽지 않으며, 일반 RPC 프록시·리셋권 사용·대화·모델 실행 기능은 없습니다.
- 로컬 서버는 일회용 접속 토큰을 세션 쿠키로 교환하고, 브라우저는 교환 뒤 URL에서 토큰을 지웁니다. 서버는 Host·Origin·요청 헤더와 쿠키를 확인합니다. 쿠키는 `HttpOnly`, `SameSite=Strict`이며 인증 요청 때마다 7일 만료 기간을 갱신합니다. 앱을 종료하면 만료 전이라도 세션을 폐기합니다.
- 응답은 `no-store`로 제공하고 CSP 등 브라우저 보안 헤더를 적용합니다. 외부 CORS, CDN, 분석 도구, 데이터베이스는 사용하지 않습니다.
- 계정 조회 결과는 화면용으로 정규화합니다. 원본 응답·표준 출력·stderr는 로그에 남기지 않습니다. 원본 계정 ID·이메일·리셋권 ID·Codex 인증 토큰은 브라우저에 보내지 않으며, 계정 상태 구분에는 일방향 digest를 사용합니다.
- 조회 결과와 캘린더 선택 상태는 메모리에만 있습니다. 알림 설정·중복 방지 기록은 브라우저 저장소에 보관하며, 기록에는 원본 ID 대신 일방향 digest를 사용합니다. 포트가 바뀌어 앱 주소가 달라지면 이전 알림 설정은 적용되지 않습니다.
- 앱은 로컬 조회 도구입니다. 같은 PC의 악성 프로그램·탈취된 OS 계정·브라우저 확장에 대한 방어 기능이나 외부 배포용 인증을 제공하지 않습니다. 공개 서버나 역방향 프록시를 통해 노출하지 마세요.
- 조회는 설치된 Codex CLI의 App Server 인터페이스 형식에 의존합니다. 호환되지 않는 응답은 오류로 안내합니다.

## 개발 및 확인

```sh
npm test
npm run check
```

- `npm test`: Node 기본 테스트 러너로 조회·정규화·인증·오류 처리·리셋 추천·캘린더·알림·화면 상태를 확인합니다. 테스트는 합성 데이터를 사용합니다.
- `npm run check`: 서버와 주요 모듈의 JavaScript 구문을 확인합니다.
- 브라우저 시각 검사는 개발 의존성과 Chromium이 필요하며, 합성 서비스를 사용해 계정이나 upstream API에 접속하지 않습니다. 화면 폭 320·375·640·768·1280px, 키보드 포커스, 밝은·어두운 모드, reduced motion, 조회 오류 화면 등을 확인합니다.

  ```sh
  npm install
  npx playwright install chromium
  npm run test:browser
  ```

- `VISUAL_QA_OUTPUT_DIR`을 지정하면 스크린샷을 해당 폴더에 저장합니다. 기본 저장 위치는 테스트에 따라 임시 폴더 또는 `.tmp/check/reset-calendar`입니다.
