# Usage plan implementation contract

## Goal and constraints

Prevent reset-credit expiry while maximizing current weekly allowance and showing the next credit's deadline gap. Read-only app: never redeem credits or execute models. No dependencies, storage of usage/history/input, credentials or external assets. Preserve existing tabs, KST format, light/dark palette, motion/accessibility, polling and security. Original checkout has unrelated uncommitted test cleanup: leave it untouched. Use TDD and apply_patch. Workers never spawn agents. Each worker commits only its scope and reports RED/GREEN, full npm test results, changed paths, commit and concerns.

## Shared interfaces (freeze before parallel work)

`buildUsagePlan(snapshot, { now = Date.now()/1000, stale = false, refreshing = false, ratePerDay = null, rateSource = 'auto' } = {})` in public/usage-timing.mjs. now and all returned timestamps are Unix seconds; snapshot timestamps are already seconds. Existing recommendUsage remains backward compatible and takes milliseconds. No DOM, timers, I/O or mutation in buildUsagePlan.

Return every field even when unavailable:
- `state`: 'ready' | 'not-ready' | 'refreshing' | 'refresh-needed' | 'server-restricted' | 'incomplete'
- `code`, `title`, `reason`: strings; actionable advice only when state ready.
- `queriedAt`, `targetAt`, `requiredRatePerDay`, `ratePerDay`, `exhaustsAt`, `remainingAtTarget`: finite numbers or null.
- `rateSource`: 'auto' | 'manual'; `coverage`: 'complete' | 'partial' | 'count-only' | 'unavailable'.
- `firstCredit`, `nextCredit`: null or { number, title, expiresAt, deadlineAt, resetType }. deadlineAt = max(now, expiresAt - 3600). Only status available and known future expiry qualify; don't mutate input or infer eligibility from count.
- `firstUseAt`: number or null. Null when natural weekly reset is the first target; otherwise min(exhaustsAt, first deadline), bounded at now. With no rate use first deadline, labeled deadline not depletion estimate.
- `nextGapSeconds`, `nextRequiredRatePerDay`, `nextRemainingPercent`: numbers or null. nextGapSeconds = max(0, next deadline - firstUseAt); when gap zero do not divide. Values after a credit are explicitly a 100% weekly refill SCENARIO, never a guaranteed outcome. Only calculate scenario when first resetType is codexRateLimits, else warn unknown effect and omit numeric scenario. If known natural reset lies inside the scenario interval, stop projection at that reset and require requery rather than projecting through it.
- `events`: array { kind: 'now' | 'weekly-reset' | 'credit-use' | 'credit-expiry', at, label, creditNumber: number|null, assumed: boolean }. Actual reset/expiry events are facts about schedule, not guarantees of refill. Include current, weekly reset, first use if any and first/next expiry. Sort by at with stable ordering.
- `segments`: array { kind: 'estimate' | 'scenario', fromAt, toAt, fromPercent, toPercent }. Do not draw unknown intervals. Clamp percent 0..100, finite timestamps, no backwards segments; split at depletion to show flat zero rather than spreading decline over the whole interval. Scenario from firstUseAt at 100 to next deadline OR intervening known natural reset, whichever earlier. no extrapolated repeated five-hour or weekly resets.
- `warnings`: array of user-visible strings (coverage limits, unknown effects, optimistic rate assumption, five-hour restriction, expired credits, coincident deadlines).

Planning math: eligible credits sorted by expiry then number (stable). now invalid, query future/invalid, resets invalid/passed, stale, refreshing, server blocked all suspend actionable plan. Reuse existing recommendUsage guards, but weekly/five-hour 0 is a ready plan with constraint warning (never claim ordinary use allowed). Current target is min(weekly resetsAt, first deadline if exists). If no credit, current target is weekly reset and recommend conserving/using current allowance based on existing advice. durationDays=(target-now)/86400; requiredRate=remaining/durationDays for positive duration only; at zero duration rate null and immediate warning. Valid rate finite >0 (manual UI validation handled outside engine). exhaustion = now + remaining/rate*86400 (current snapshot estimate, not guaranteed). remainingAtTarget=max(0, weekly remaining - rate*durationDays). First deadline inside 1h => immediate review. Natural reset <= first deadline => prioritize requery at reset, no firstUseAt/second scenario. Otherwise exhaustion <= deadline => use-until-depleted then requery and consider credit; else use-until-deadline then consider credit, explicitly show remaining allowance sacrificed. Permission null => conditional advice. Partial details => '조회된 항목 중', count-only/no known eligible credits => do not invent dates. Next deadline gap uses safety deadlines and firstUseAt, not merely expiry subtraction. Same expiry with multiple credits must be warned even if earlier predicted firstUseAt makes a positive gap.

`createUsagePlanView(container)` in public/usage-plan-view.mjs returns { update(plan), clear(), destroy() }. Owns display only; does not recompute math or control inputs/polling. Can use document via container.ownerDocument. No innerHTML with data. Memoize meaningful plan render to avoid reconstructing SVG on every clock tick. Plot times clipped/scaled to events/segments horizon; label collisions handled with event rows below. Semantic SVG title/description plus text equivalents. No animations needed.

- Main recommendation retains existing IDs. Add `usage-plan-summary` (compact text), `usage-plan-first-use`, `usage-plan-leftover`, `usage-plan-next-gap` inside recommendation.
- schedule panel adds section `usage-plan`, fieldset with radio name `usage-plan-rate-mode` values auto(default)/manual, input `usage-plan-rate` type number min 0.1 step any label '예상 하루 소모량 (%p/일)', text `usage-plan-input-error` (aria-live polite), hint calendar 24h and memory-only. Radio/input touch size >=44px. Manual rate UI allows any finite >0, min attribute matches preferred entry but values >0 below .1 also valid via step any and JS (use min 0 instead if needed).
- renderer container `usage-plan-chart` in same section. Renderer displays title/reason, target/rate/remaining summaries, source, warnings, SVG event timeline, SVG remaining chart and full KST event list. Main compact fields are filled by app, not renderer.
